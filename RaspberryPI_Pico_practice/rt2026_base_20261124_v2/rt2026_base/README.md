# RT2026 基礎プログラム（2026-11-24 第2版）

2026年モデルのロボトレーサ（Raspberry Pi Pico 2）の、配布用の基礎プログラムです。
ピンは、ロボット仕様書（20261122）の表1-5に合わせてあります。

**この版は、実機ではまだ動かしていません。** PCの上で確かめた内容は、12章にあります。
新しい基板では、5章の順番で、部品を1つずつ確かめてから走らせてください。

## 1. 最初の版（11/24 20時ごろの zip）から変わった所

- **記録**：1回の全消去で、走行を5回まで記録できます（走行1は64.5秒、走行2〜5は48.9秒まで）。
- **キャリブレーション**：スイッチ0をもう一度押すと終わります（押さなくても6秒で終わります）。前の版は4秒で固定でした。
- **安全のための停止を3つ追加**
  - duty を出しているのに、車輪が回っていない、または逆に回っているときに止まる（エンコーダかモーターの向きが逆のとき）
  - 電池の電圧が 6.6V より低いときは、走り出さない
  - 見張りのタイマー（ウォッチドッグ）：1msの割り込みが250msより長く止まったら、マイコンをリセットしてモーターを止める
- **既定値の変更**：`DUTY_LIMIT` を 0.8 → 0.5、`MOTOR_R_SIGN` を +1 → -1（右のモーターの向き。推測なので、5章の順番7で確かめます）
- **`board.h` に `SENSOR_ADC_CH` を追加**：センサーの並びが違っていたら、ここの数字を入れ替えるだけで済みます。
- **動作確認メニュー**：`b`（両方のモーターを前進の向きに回す）を追加。Picoの基板の上のLED（GP25）も、0.5秒ごとに点滅します。
- **記録の `now_angular_velocity`**：ジャイロを使わない間は、左右の車輪の速さの差から計算した角速度を入れます。
- **訂正**：前の README の「A/D変換の値が 0〜1023 に収まらなければ、ICは MCP3208」は誤りでした。
  10ビットの設定のままで、MCP3008 でも MCP3208 でも 0〜1023 と読めます。設定を変える必要はありません。

## 3. ビルドと書き込み

1. VS Code の Raspberry Pi Pico 拡張機能で、ボードを **Pico 2** にして新しいプロジェクトを作る。
2. このフォルダの中身を、プロジェクトのフォルダにコピーする。
3. `CMakeLists.txt` は、拡張機能が作った物の先頭（「DO NOT EDIT」の部分）を残し、
   `project(...)` から下を、このフォルダの `CMakeLists.txt` の `project(...)` から下に置き換える。
   プロジェクトの名前を変えたときは、`rt2026_base` を全部その名前に直す。
4. ビルドして、`.uf2` を書き込む。

ビルドでつまずいたときは、`prebuilt/rt2026_base.uf2` を先に書き込めば、5章の動作確認だけは進められます
（BOOTSEL ボタンを押しながらUSBをつなぎ、出てきたドライブに、このファイルをコピーします）。
`board.h` や `params.h` を変えた後は、自分でビルドした `.uf2` を使ってください。

## 4. 操作

| 操作 | 動き |
|---|---|
| スイッチ0を短く押す | 走行開始。1秒後に動き出す。キャリブレーションがまだのとき、電池の電圧が低いときは、走らない |
| スイッチ0を1秒長押し | キャリブレーションを始める。機体をラインの上で左右に動かし、スイッチ0をもう一度押すと終わる（押さなくても6秒で終わる） |
| スイッチ1を2秒長押し | フラッシュメモリの全消去（標準10秒、最大30秒）。始めと終わりに、長いブザー |
| 走行中に、どちらかのスイッチを押す | 停止（動き出す前の1秒の間も同じ） |
| USBシリアルの `1`〜`5` | その番号の走行の記録を、CSVで出す |
| USBシリアルの `d` | いちばん新しい走行の記録を、CSVで出す |
| USBシリアルの `s` | 状態を表示する（電源電圧、キャリブレーション、走行ごとの記録の件数） |
| USBシリアルの `h` | 基板の動作確認メニュー |
| USBシリアルの `E`、続けて `y` | フラッシュメモリの全消去 |
| USBシリアルの `?` | 操作の説明 |

USBシリアルの操作は、待ちの状態（LED0 が0.5秒ごとに点滅）のときだけ受け付けます。

### 走行の流れ

機体を、スタートのマーカーの手前に置きます。スイッチ0を押すと、1秒後に加速しながら走り出し、
右側のマーカーの1個目（スタート）を過ぎ、2個目（ゴール）を過ぎたら、減速して止まります。
交差（左右のマーカーセンサーが同時に白を見る所）は、マーカーとして数えません。

走行は、次のどれかで止まります。

| 止まり方 | 条件 |
|---|---|
| ゴールのマーカーで止まった | 右側のマーカーの2個目を過ぎた |
| スイッチで止めた | 走行中に、どちらかのスイッチを押した |
| ラインを見失って止まった | ラインセンサー6個とも白が見えない状態が、0.3秒続いた |
| 車輪が回っていないか、逆に回っている | duty が25%より大きいのに、その車輪が止まったまま0.3秒、または後ろ向きに回ったまま0.1秒 |
| 時間切れ | 走り始めてから120秒 |

どうしても止まらないときは、基板のリセットのスイッチを押します。マイコンのピンが全部入力に戻り、モーターが止まります。

### 記録

- 1msごとに1件（16バイト）を記録します。走行1は 64,512件（64.5秒）、走行2〜5は 48,896件（48.9秒）まで入ります。
  いっぱいになったら、記録だけを止めて、走行は続けます。
- スイッチ0を押すたびに、走行1、走行2 … の順に、次の場所へ記録します。
- 5回分を使い切った後と、全消去がまだのときは、**記録なしで走ります**（始まりのブザーが、低い音で2回になります）。
- もう一度記録するには、必要な走行を `1`〜`5` で読み出してから、全消去をします。
- 途中で電源が切れても、そこまでに書いたページ（16件ごと）は残ります。その回は「使った」と数えます。
- 動作確認メニューの `9` → `y`（フラッシュの確認）も、走行1回分の場所を使います。

### ブザーとLED

| 鳴り方 | 意味 |
|---|---|
| 起動時、高い音で短く2回 | フラッシュメモリと通信できた |
| 起動時、低い音で長く1回 | フラッシュメモリと通信できていない（記録なしで走れます） |
| 起動時、低い音で8回 | 前回、プログラムが途中で止まり、見張りのタイマーがリセットした（今回は、見張りのタイマーを使わずに動く） |
| スイッチ0を押した直後、高い音で短く1回 | 走行開始（記録あり） |
| スイッチ0を押した直後、低い音で短く2回 | 走行開始（記録なし） |
| スイッチ0を押した直後、低い音で短く4回 | キャリブレーションがまだなので、走らない |
| スイッチ0を押した直後、低い音で短く6回 | 電池の電圧が低いので、走らない |
| スイッチ0を押して1秒後、短く1回 | 動き出す |
| キャリブレーションの後、高い音で短く2回 | 成功 |
| キャリブレーションの後、低い音で長く1回 | 失敗（白と黒の差が小さいセンサーがある）。前の値に戻る |
| 走行中、低い音で短く1回 | スタート、ゴールのマーカーを過ぎた |
| 走行中、低い音で長く1回 | 安全のための停止 |
| 走行の後、高い音で短く2回 | 記録に欠けが無い（記録なしで走ったときも同じ） |
| 走行の後、低い音で長く | 記録に欠けがある |
| 全消去の始めに長く、終わりに高い音で長く | 全消去が終わった |
| 全消去の後、低い音で8回 | 全消去に失敗した |

| LED | 点き方 | 意味 |
|---|---|---|
| Picoの基板の上のLED | 0.5秒ごとに点滅 | 1msの割り込みが動いている |
| LED0（GP17） | 0.5秒ごとに点滅 | 待ち |
| LED0（GP17） | 速い点滅 | キャリブレーション中、全消去中 |
| LED0（GP17） | 点きっぱなし | 走行中（動き出す前の1秒を含む） |

## 5. 新しい基板で最初に確かめる順番

機体は台に載せて、**車輪を浮かせておきます**。USBをつなぎ、シリアルの画面で `h` を押して、順に進めます。
1つでも合わない所があれば、そこで止めて、`board.h` を直してビルドし直してから、先へ進みます。

| 順 | 操作 | 正しいときの様子 | 合わないときに直す所 |
|---|---|---|---|
| 0 | 電源を入れる | Picoの基板の上のLEDが点滅。シリアルに「フラッシュメモリ : 通信OK」（見逃したら、`s` でもう一度出ます） | 6章の表 |
| 1 | `1` スイッチとLED | 押している間だけ 1 になる。LED0 が点滅する | `SW_PRESSED_LEVEL`、`PIN_LED0` |
| 2 | `2` ブザー | ド・ミ・ソと鳴る | `PIN_BUZZER` |
| 3 | `3` ラインセンサー | 白の上で raw が小さく、黒の上で大きい。8個とも値が変わる | `LINE_LED_ON_LEVEL` |
| 4 | `3` の続き | 右端のセンサーを白に載せると、画面のいちばん左の列（sensor[0]）が小さくなる。機体をラインの右にずらすと、「ずれ」が正になる | `SENSOR_ADC_CH`、`LINE_DISP_SIGN` |
| 5 | `4` 電源電圧 | テスターで測った電池の電圧と、ほぼ同じ値になる（分圧の抵抗の誤差の分は、ずれます） | `VBAT_R_TOP`、`VBAT_R_BOTTOM` |
| 6 | `5` エンコーダ | 車輪を前進の向きに手で回すと、数が増える。タイヤ1回転で840 | `ENC_L_SIGN`、`ENC_R_SIGN` |
| 7 | `6`、`7`、`b` モーター | 車輪が前進の向きに回り、回した側の数が増える。`b` で左右とも正の速さ | `MOTOR_L_SIGN`、`MOTOR_R_SIGN` |
| 8 | `9` → `e`（全消去）、続けて `9` → `y` | 「結果 : 合格」 | 配線（SCK=GP2、MOSI=GP3、MISO=GP4、CS=GP5） |
| 9 | `q` で戻り、スイッチ0を1秒長押し | 機体を左右に動かして、もう一度押すと「キャリブレーションが終わりました : 成功」 | 画面に出たセンサーを、白と黒の両方に通す |
| 10 | 走行 | `RUN_SPEED_MPS` を 0.3 にして、短い直線から試す | 6章の表、`params.h` |

補足です。

- 順番3の画面は、左から sensor[0]（右端）〜[5]（左端）、[6]（スタート・ゴール側のマーカー）、[7]（コーナー側のマーカー）です。
  「白黒」の8桁だけは、左から sensor[7]、[6]、[5] … [0] の順です。
- 順番8の `9` → `y` は、全消去の後でないと「記録を始められませんでした」と出ます。先に `e` をします。
- 機体を持ち上げたままスイッチ0で走行を始めると、0.3秒で「ラインを見失って止まった」になります。
  センサーがラインを見ていないためで、正しい動きです。

## 6. うまくいかないとき

| 様子 | 見る所 |
|---|---|
| シリアルに何も出ない | Picoの基板の上のLEDが点滅していれば、プログラムは動いています。シリアルの画面を開き直して `?` を押します |
| Picoの基板の上のLEDが点滅しない | 書き込みができているか。ボードが Pico 2 か（Pico 2 W では、このLEDは点きません） |
| 「フラッシュメモリ : 通信OK」と出ない | フラッシュメモリの配線と電源。出なくても、記録なしで走れます |
| 起動のブザーが低い音で8回鳴る | 前回、1msの割り込みが250msより長く止まり、見張りのタイマーがマイコンをリセットしました。直前に変えた所を確かめます。今回の起動では、見張りのタイマーを使いません（リセットのスイッチを押すか、電源を入れ直すと、また使います）。切り分けのために止めるときは、`params.h` の `USE_WATCHDOG` を 0 にします |
| 書き込んだ直後にだけ、低い音で8回鳴る | プログラムが止まったのではなく、PCの上で想定した動きと、実機の動きが違っています。そのまま使えます。起きたことを控えておいてください |
| VS Code からの書き込みが始まらない | BOOTSEL ボタンを押しながらUSBをつないで書き込みます。次からも始まらないなら、`params.h` の `USE_WATCHDOG` を 0 にします（見張りのタイマーと書き込みの関係は、PCの上の模型でしか確かめていません） |
| 押していないのにスイッチが 1 のまま、または押しても 0 のまま | `SW_PRESSED_LEVEL` を逆にする |
| raw が8個とも同じ値のまま動かない | `LINE_LED_ON_LEVEL` を逆にする。A/D変換ICの配線（CS=GP14） |
| キャリブレーションが失敗する | 画面に出た番号のセンサーが、白と黒の両方を通っていません。マーカーセンサー（[6] と [7]）は外側にあるので、機体を大きく動かします |
| 「電池の電圧が低いので、走行を始めません」と出るが、電池は充電してある | 順番5で、テスターの値と比べます。違うときは `VBAT_R_TOP` と `VBAT_R_BOTTOM`。`VBAT_LOW_V` を 0 にすると、この確認をしません |
| 走り出してすぐ「車輪が回っていないか、逆に回っている」で止まる | 電池がつながっているか。順番6と7をやり直す |
| ラインから離れる向きに曲がる | 順番4をやり直す（`SENSOR_ADC_CH`、`LINE_DISP_SIGN`） |
| ラインの上で左右に振れる | `OMEGA_GAIN` を小さくする（例：0.7。小さくしすぎると、きついカーブで曲がりきれなくなります）。`RUN_SPEED_MPS` を下げる |
| カーブで曲がりきれない | `RUN_SPEED_MPS` を下げる。`OMEGA_GAIN` を大きくする。duty が上限に張り付いていたら `DUTY_LIMIT` を上げる |
| スタートのマーカーを過ぎてすぐ止まる、ゴールで止まらない | 順番3で、sensor[6] がマーカーの上で白（norm が60より大きい）になるかを見ます。左右のマーカーセンサーが逆なら、`SENSOR_ADC_CH` の最後の2つの数字（6 と 7）を入れ替えます |
| 走行の後に「欠けがあります」と出る | 画面の「捨てたページ数」「書き込みエラーの回数」を控えます。モーターの雑音がフラッシュの通信に入っている疑いがあります |

## 7. 走りの調整（`params.h`）

| 値 | 既定 | 意味 |
|---|---|---|
| `RUN_SPEED_MPS` | 0.5 | 定常の速さ [m/s]。先生のサンプルは 0.7 |
| `RUN_ACCEL_MPS2`、`RUN_DECEL_MPS2` | 1.0 | 加速度と減速度 [m/s²]。先生のサンプルは 2.0 |
| `OMEGA_GAIN` | 1.0 | ずれから決めた目標の角速度に掛ける倍率 |
| `DUTY_LIMIT` | 0.5 | モーターに出す duty の上限。速さを上げるときは、一緒に上げる |
| `KP_SPEED` | 5.0 | 車輪の速さの誤差に掛ける値 [V/(m/s)]（仕様書 4.1.5） |
| `USE_GYRO` | 0 | 1 にすると、ジャイロで旋回を補正する（仮のドライバ。実機では未確認） |

ゴールのマーカーを過ぎてから止まるまでの距離は、およそ「速さ × 速さ ÷（2 × 減速度）」です
（例：0.5m/s、1.0m/s² なら 0.125m。1.0m/s、1.0m/s² なら 0.5m）。速さを上げるときは、`RUN_DECEL_MPS2` も上げます。

次の表は、**PCの上の模型で走らせた結果**です。モーターやタイヤの実際の特性は入っていないので、実機でも同じ数字になるとは言えません。
「どの値を、どちらに動かすと、どうなるか」の向きを知るための物として見てください。
数字は、ラインからの最大のずれです。コースAは半径250〜300mmのカーブと交差、コースCは半径100〜150mmのカーブとS字です。

| 設定 | コースA | コースC |
|---|---|---|
| 0.3m/s | 5.5mm | 19.0mm |
| 0.5m/s（既定） | 5.4mm | 19.3mm |
| 0.7m/s、加速度と減速度 2.0（先生のサンプルの値） | 6.1mm | 20.7mm |
| 1.0m/s、`DUTY_LIMIT` 0.5 のまま | 8.9mm | ラインを外れて停止 |
| 1.0m/s、`DUTY_LIMIT` 0.8 | 8.0mm | 26.6mm |
| 1.5m/s、`DUTY_LIMIT` 0.8 | 14.3mm | ラインを外れて停止 |
| 0.5m/s、`OMEGA_GAIN` 0.5 | 18.7mm | ラインを外れて停止 |
| 0.5m/s、`OMEGA_GAIN` 0.7 | 16.1mm | 31.7mm |
| 0.5m/s、`OMEGA_GAIN` 2.0 | 5.0mm | 10.0mm |

模型では `OMEGA_GAIN` を大きくするほど、ずれが小さくなりました。ただ、模型にはモーターの遅れやタイヤの滑りが入っていません。
実機では、大きくすると左右に振れやすくなると考えています（推測です）。

## 8. 記録の読み方

`1`〜`5` か `d` を押すと、次の形で出ます。`=== START DUMP ===` から `=== END DUMP ===` までがCSVです。
「走行ログ ビューア」に貼るか、行を保存して表計算ソフトで開きます。

| 列 | 中身 |
|---|---|
| `sensor_displacement` | ラインからのずれ（-100〜+100。機体がラインの右にあるときが正） |
| `sensor_binary` | センサー8個の白黒（ビット0 = sensor[0] … ビット7 = sensor[7]。白が1） |
| `target_speed`、`left_speed`、`right_speed` | 目標の速さ、左右の車輪の速さ [mm/s] |

プログラム全体の模型では、次の場面を動かしました。

- 新しい基板での最初の走行、全消去、5回の記録と6回目（記録なし）、記録の読み出し
- 配線の間違い4種類（右エンコーダが逆、右モーターが逆、車輪が動かない、左エンコーダが逆）：どれも、進んだ距離が0.1m以内で止まった

- キャリブレーションの失敗、動作確認メニューの全部の項目、スイッチの向きが `board.h` と逆の基板

- カーブと交差のあるコース2種類

- 見張りのタイマーによるリセットの後の起動：注意の文字が出て、見張りのタイマーを使わずに動いた

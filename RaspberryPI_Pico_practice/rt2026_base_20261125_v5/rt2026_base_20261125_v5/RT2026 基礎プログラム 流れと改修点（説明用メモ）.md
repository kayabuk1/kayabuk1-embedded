# RT2026 基礎プログラム 流れと改修点（説明用メモ）

Nov 25, 2026 · @まさ

## 1. 全体の分担

プログラムは、1msごとの割り込みと、main のループの2つで動きます。割り込みがセンサーを読んでモーターを動かし、main がフラッシュメモリへの書き込みと、操作の受け付けをします。

| 動く所 | ファイル | すること | 主な関数 |
| --- | --- | --- | --- |
| 1msの割り込み | `control.c` | センサー・エンコーダ・スイッチを読む。状態を進める。モーターを動かす。記録を1件渡す | `control_timer_cb()` |
| main のループ | `main.c` | フラッシュメモリへの書き込み。スイッチとシリアルの操作の受け付け。全消去、記録の読み出し、動作確認メニュー | `flash_task()`、`do_start_run()`、`do_erase()`、`selftest_menu()` |

- **SPIの使い分け**：フラッシュメモリ（SPI0）は main だけが使います。A/D変換ICとジャイロ（SPI1）は割り込みだけが使います。同じSPIを両方から使うと、通信の途中で相手に割り込まれて、値が壊れるためです。
- **例（走行中の記録）**：割り込みが `log_put()` で1件（16バイト）を渡します。16件（256バイト）たまるごとに、main の `flash_task()` が、フラッシュメモリの1ページに書きます。
- **設定の置き場所**：ピンと向きは `board.h`、走りの調整は `params.h`、モーターの制御の定数は `encoded_geared_motor.h` です。

## 2. 1msの割り込みの流れ

`control.c` の `control_timer_cb()` は、1msごとに、次の5つを上から順に行います。どの状態のときも、1から5を1回ずつ通ります。

1. **読む**
   - `line_sensor_sample()`：ラインセンサー6個とマーカーセンサー2個を、A/D変換ICから読む。ラインからのずれ（-100〜+100）を計算する
   - `battery_update()`：電源電圧。`sw_update_1ms()`：スイッチ。`beepProcess()`：ブザー
   - `motor_control()` を左と右に1回ずつ：エンコーダを読み、車輪の速さと duty を計算する（担当の方の関数）
2. **判定する**
   - `goal_marker_passed()`：ゴール側のマーカー（`sensor[6]`）を通り過ぎたか。交差は、マーカーとして数えない
   - ラインからのずれ（`disp`）から、目標の角速度（`target_omega`）を決める。表 `targetAngularVelocity` を引いて、今の速さを掛ける
3. **状態を進める**
   - 先に、安全のための停止を確かめる（3章の表）
   - `switch (state)`：走行中は `trace_step()` が、duty を上限（`DUTY_LIMIT`）に収めて、`motor_set()` でモーターに出す。続けて、次の回の目標の速さと角速度を書き込む
4. **記録する**：走行中は、今の値を `now_sensors_data` に入れて、`log_put()` に渡す
5. **知らせる**：LED を点滅させる。見張りのタイマーに `watchdog_update()` で「動いている」と知らせる。この割り込みにかかった時間を覚える

例（ずれが 50 のとき）：表 `targetAngularVelocity` の50番目の値は 391.9 deg/s です。速さが 0.5 m/s なら、目標の角速度は 391.9 × 0.5 × `OMEGA_GAIN`（1.0）で、約196 deg/s です。ずれが正（機体がラインの右）なので、左に曲がります。

duty は、前の回の割り込みで書き込んだ目標から計算されます。モーターに出すのは、走行中だけです。

## 3. 状態の進み方

走行は、`control.h` の `run_state_t` の状態を、上から下へ1つずつ進みます。右側のマーカーの1個目でスタート、2個目でゴールです。

&#91;embedded content: 状態の進み方 · 9つの状態と、安全のための停止\]

図の左の線は、走行が終わって待ちへ戻る流れです。スイッチ0での走行の開始は、キャリブレーションが済んでいるときだけ受け付けます。加速の途中でゴールのマーカーを通り過ぎたときは、定速を飛ばして、減速へ進みます。

安全のための停止は、動き出す前の待ちと走行中に、1msごとに確かめます。どれかに当たると、ブレーキをかけて「モーター停止」へ進みます。

| 止まる理由（`stop_reason_t`） | 条件 | `params.h` の値 |
| --- | --- | --- |
| `STOP_SWITCH` | どちらかのスイッチが押された | なし |
| `STOP_LINE_LOST` | ラインセンサー6個とも、白がほとんど見えない状態が 300 ms 続いた | `LOST_STOP_MS` |
| `STOP_ENCODER` | duty を 10% より多く出しているのに、車輪の速さが 0.03 m/s より遅い状態が 500 ms 続いた。または、逆向きに 0.15 m/s より速く回る状態が 100 ms 続いた | `STALL_DUTY`、`STALL_SPEED_MPS`、`STALL_STOP_MS`、`REVERSE_SPEED_MPS`、`REVERSE_STOP_MS` |
| `STOP_TIMEOUT` | 走り始めてから 120 秒たった | `RUN_MAX_MS` |
| `STOP_GOAL` | ゴールのマーカーの後、減速して、目標の速さが 0.05 m/s 以下になった（正常な終わり方） | `RUN_DECEL_MPS2` |

`STOP_ENCODER` は、エンコーダかモーターの向きが逆のときや、配線が外れているときに、機体が速く走り出すのを止めるための物です。

## 4. 改修した所

担当の方のファイルで変えたのは、組み込みに必要な10か所です。ファイルの中にも、同じ記号（【変更A】など）でコメントを入れてあります。

| 記号 | ファイルと関数 | 変えた内容 | 理由 |
| --- | --- | --- | --- |
| A | `encoded_geared_motor.c` の `motor_data_input()` | エンコーダの数に、`ENC_L_SIGN`／`ENC_R_SIGN` を掛ける | 向きが逆の基板でも、`board.h` の1行で直せるようにする |
| B | `encoded_geared_motor.c` の `motor_set()` | duty に `MOTOR_L_SIGN`／`MOTOR_R_SIGN` を掛ける。IN1 と IN2 の役割を、仕様書 3.6 の表（duty が正のとき IN1=H、IN2=PWM）に合わせた | 元は、表の「duty が負」の行と同じ出し方だった |
| C | `encoded_geared_motor.c` の `motor_free()`（追加） | IN1 と IN2 を両方 L にする | ブレーキのままだと、車輪を手で回しにくく、エンコーダを確かめにくい |
| D | `encoded_geared_motor.h` の `K_BACK_EMF_R` | 0.00332 → 0.00382 | 配る物の既定は、左右とも仕様書の値にする |
| E | `encoded_geared_motor.h` の `SPEED_ERROR_PER_WHEEL`（追加）と、`.c` の `p_control()` | 速さの誤差を、車輪ごとの目標との差で計算する。0 にすると、元の計算（中心の速さとの差）に戻る | 仕様書 4.1.5 の式に合わせる |
| F | `encoded_geared_motor.h` の `K_SPEED_ERROR` | 0.3 → 5.0 | 仕様書の値。E とセット |
| G | `encoded_geared_motor.h` の `ENCODE_INPUT_PIN_L`／`R` | `BOARD_EDU` が 1 のときだけ、16 と 13 にする。機体の基板の 6 と 8 は、元のまま | 教育用の実験基板で試すため |
| 1 | `l3gd20h.h` | `#ifndef` と `#endif` を足した | 同じファイルが2回読み込まれても、問題が出ないようにする |
| 2 | `l3gd20h.h` | ピンを SPI1（SCK=GP10、MOSI=GP11、MISO=GP12、CS=GP13）にした。元は spi0 の 6、7、4、5 | 新しい基板のピン表に合わせる |
| 3 | `l3gd20h.c` の `l3gd20_cs_select()` | CS を下げる前に、SPI をモード3に設定し直す | SPI1 を、A/D変換IC（モード0）と共用しているため |

- **E と F を元に戻す方法**：`SPEED_ERROR_PER_WHEEL` を 0、`K_SPEED_ERROR` を 0.3f にします（2行）。モーターの担当の方には、既定を仕様書の式に変えたことを伝えてください。
- **E と F の根拠**：PCの上の模型（コース2種類）では、ラインからの最大のずれが、仕様書の式で 5.5 mm と 18.6 mm、元の計算で 14.8 mm と 43.1 mm でした。実機では、まだ比べていません。
- **そのほかのドライバ**：A/D変換IC（`adc_mcp3208or3008/`）は、ピンを SPI1 にして、MCP3008（10ビット）に合わせました。ブザー（`buzzer/`）は、ピンの番号だけを変えました。

先生のサンプル（`rt2026_repeating_timer.c`）の流れに、基礎プログラムの側で足した物は、次の5つです。

- 状態を2つ：`STATE_START_DELAY`（スイッチを押してから動き出すまでの1秒）と、`STATE_DONE`（main が記録を閉じるのを待つ）
- 安全のための停止（3章の表）と、見張りのタイマー（`params.h` の `USE_WATCHDOG`）
- 記録を5回分に分けた（`flash_log/`）。スイッチ1の2秒長押しで全消去
- 基板の動作確認メニュー（`selftest.c`、シリアルの `h`）
- 設定の切り替え：どの基板かは `board.h` の `BOARD_EDU`、どのマイコンかは `CMakeLists.txt` の `PICO_BOARD`

## 5. まだ確かめていない所と、入っていない物

機体の基板では、まだ1回も動かしていません。実機で確かめたのは、教育用の実験基板（Pico）での範囲までです。

| 区分 | 内容 |
| --- | --- |
| 実機で確かめた（11/25、実験基板と Pico） | スイッチ、ブザー、LED、つまみでの左エンコーダ、起動のメッセージ、フラッシュメモリの5回分の記録（1000件ずつ、5回とも合格）、長押しでの全消去、全消去の後に4MBの全体が消えていること（第5版）、待ちのときの1msの割り込みにかかった時間（第5版。平均 304 us、最大 約400 us） |
| PCの上の模型だけで確かめた | 走行（19場面、183項目、失敗0）、配線の間違いで止まること、見張りのタイマー |
| まだ確かめていない | ラインセンサー（A/D変換IC）、ジャイロ、車輪のエンコーダ、モーター、機体の基板のピンと向き、走行中に1msの割り込みが 1000 us に収まるか |
| まだ入っていない | コース情報の保存、UARTでの記録の転送、加速度のぶんの電圧（仕様書 4.1.7。担当の方の `p_control()` に、まだ入っていない）、キャリブレーションの結果の保存 |

機体の基板が来たら、README の5章の順番0〜11で、部品を1つずつ確かめます。向きが合わない所は、`board.h` の値（例：`MOTOR_L_SIGN`）を1行変えて直します。

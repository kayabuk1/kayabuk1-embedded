# AT25SF321B 実機測定のまとめ（2026-11-18）

## 0. この表の読み方

- **測った物**：Raspberry Pi Pico（RP2040、ブレッドボード）と AT25SF321B。試験プログラムは `Sample_AT25SF321B_SPI_Flash_Memory.c`。
- **「BUSY=0 と読めた回数」**：消去や書き込みの途中で、`at25sf.c` の `wait_bits_clear()` がステータスレジスタ1（SR1）を読んだとき、BUSY=0 と読め、その後また BUSY=1 と読めた回数です。`AT25SF_diag_t` の `busy_again` にあたります。合否には使わない、参考の値です。
- **数え方**：画面に出る回数は、電源を入れてからの合計です。この表では、消去の前と後の合計の差を、その消去1回の分としました。例：22番の2回目の `e` では、合計が0回から4回に増えたので、その消去1回の分は4回です。
- **「データあり」**：4KBや64KBの範囲に、すでにデータが書いてある状態での消去です。何も書いていない範囲の消去は、すぐ終わるので、回数の集計から外しました。
- **報告の時刻**：ログを貼った時刻です。測った時刻は、その少し前です。
- **`t` と `v` の列**：「合格した回数/行った回数」です。

## 1. 採用する設定

| 項目 | 設定 |
|---|---|
| SPIの速さ | `#define AT25SF_SPI_BAUDRATE ((125.0/30.0) * 1000 * 1000)`。実際の速さは 4166666 Hz（約4.17MHz） |
| WP#（3番ピン）、HOLD#（7番ピン） | プルアップ抵抗で3.3Vへ |
| ICの電源 | VCC（8番ピン）とGND（4番ピン）の間に 0.1µF のコンデンサ |
| CSをHighにした後の待ち時間 | `#define CS_HIGH_WAIT_US 2u`（`at25sf.c`） |

- この設定での測定は、下の表の17番と21番です。どちらも `t` と `v` はすべて合格です。
- 同じ `#define` で、機体の Pico 2 でも実際の速さは 4166666 Hz になります（Pico は 125MHz ÷ 30、Pico 2 は 150MHz ÷ 36）。SDK の `spi_set_baudrate()` の計算式で確かめました。機体では、まだ動かしていません。

## 3. 条件を1つだけ変えて、続けて測った組

数字は、64KBの消去（データあり）1回あたりの「BUSY=0 と読めた回数」です。かっこの中は、上の表の番号です。

### 3.1 コンデンサだけを変えた組

| 実際のSPIの速さ | コンデンサあり | コンデンサなし | 変えた順 | チップ全体の消去1回での回数（あり / なし） |
|---|---|---|---|---|
| 約10.42MHz | 53.9回（12番、0.047µF） | 108.5回（13番） | ありで測り、抜いた | 119回 / 201回 |
| 約4.17MHz | 25.4回（17番、0.1µF） | 67.2回（16番） | なしで測り、足した | 43回 / 117回 |
| 約4.17MHz | 0.5回（21番、0.1µF） | 5.2回（22番） | ありで測り、抜いた | 2回 / 8回 |

3組すべてで、コンデンサありのほうが少ない。

### 3.2 プルアップ抵抗だけを変えた組

| 実際のSPIの速さ | プルアップ抵抗あり | プルアップ抵抗なし |
|---|---|---|
| 約8.93MHz | 0回（5番） | 0.6回（6番） |
| 約31.25MHz | 6.2回（9番） | 15.5回（8番、9番の前）、35回（10番、9番の後） |

どちらの組でも、プルアップ抵抗ありのほうが少ない。ただし、組は2つだけです。

### 3.3 `CS_HIGH_WAIT_US` を変えた測定（プルアップ抵抗あり、コンデンサなし）

| 実際のSPIの速さ | 2u | 3u |
|---|---|---|
| 約8.93MHz | 2回（15番） | 0.4回（18番） |
| 約10.42MHz | 108.5回（13番） | 71回（19番） |
| 約4.17MHz | 67.2回（16番、3uの前）、5.2回（22番、3uの後） | 34.5回（20番） |

約4.17MHzでは、3u の値が、2u の2回の値の間に入っています。3u の効果は、この測定からは判断できません。1ページをICへ送る時間の平均は、3u にすると2〜3us 増えました。

| 約0.99MHz | 2527us | 約16% | 約159ms |
| 約1.008MHz | 2487us | 約16% | 約157ms |

| 約8.93MHz | 290us | 約2% | 約18ms |

- 1ページを送った後、ICが書き終えるのを待った時間の最大：約0.34〜0.35ms（速さによらない）。
- 4KBの消去：何も書いていない範囲は約0.6ms、データありは約23ms。
- 64KBの消去：何も書いていない範囲は約7.8ms、データありは約113〜171ms。
- チップ全体の消去：約0.71〜0.79秒（ほとんどの範囲が、何も書いていない状態での値）。

## 6. 言えること、言えないこと

**事実**
- データの誤りが出たのは、3番（約8.93MHz、プルアップ抵抗なし）の1回だけです。ほかの21回の測定では、約0.99MHzから約31.25MHzまで、`t` と `v` がすべて合格です。
- 「06hの後に BUSY=1 と読めた回数」は、全測定で0回です。BUSY=0 と読めても、ドライバは書き込みや消去の結果を誤っていません。
- データが正しかった測定で比べると、約8.93MHzと約15.63MHzでは、64KBの消去1回あたりの BUSY=0 と読めた回数が少なく（0〜2回）、約10.42MHzでは多い（53.9〜108.5回）。この違いは、測り直しても入れ替わっていません。
- コンデンサだけを変えた3組すべてで、コンデンサありのほうが少ない。
- 同じ条件でも、時刻が違うと回数が大きく変わる（4章）。

**分かっていないこと**
- 消去の途中で BUSY=0 と読める原因。
- 同じ条件で回数が大きく変わる原因。
- 3番のデータの誤りの原因（同じ条件の6番では出ていない）。
- `CS_HIGH_WAIT_US` を 3u にしたときの、回数への効果。

**推測**
- コンデンサは、消去中のICの電源の電圧の揺れを小さくして、回数を減らしている。3組の向きがそろっていることが根拠ですが、組が3つだけなので、強い証拠ではありません。

## 7. 機体（Pico 2）で確かめること

1. 機体用の設定（`PICO2350 = 1`、SPI1、GP10〜13）で `i` を送り、「SPI : 4166666 Hz」と「JEDEC ID : 1F 87 01」が出るかを見る。
2. `t`、続けて `e` → `l` → `v` を数回行う。
3. モーターを回した状態で、2. をくり返す。
4. 合否は、照合がOKか、「06hの後に BUSY=1 と読めた回数」「捨てたページ数」「書き込みエラーの回数」が0か、で見る。「BUSY=0 と読めた回数」は合否に使わない。
5. NGが出たら、速さを2MHz、1MHzの順に下げる。約1MHzでも、1ページをICへ送る時間は約2.5msで、先生が許容した範囲。
6. 機体の基板に、WP# と HOLD# のプルアップ抵抗、0.1µFのコンデンサが付いているかを、回路図で確かめる。

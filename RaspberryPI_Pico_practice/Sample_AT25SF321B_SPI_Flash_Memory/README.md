# AT25SF321B フラッシュログ（Raspberry Pi Pico）

1msごとの記録（1件16バイト）を、走行の制御を止めずにSPIフラッシュメモリへ書き、後からCSVで読み出すためのコードです。

- 割り込み（1msごと）は、16バイトをRAMのバッファに詰めるだけです。SPIは使いません。
- mainのループが、たまった1ページ（256バイト＝16件）をフラッシュに書きます。
- 電源を入れ直した後でも、PCからCSVで読み出せます。

**2026-11-16の時点で、実機（本物のICと配線）ではまだ動かしていません。** 確かめた範囲は、末尾の「確かめたこと」にあります。最初に `i` と `t` のコマンドで、通信と書き込みを確かめてください。

## ファイル

| ファイル | 層 | 役割 |
| --- | --- | --- |
| `at25sf.h` / `at25sf.c` | ドライバ | SPIでICと話す（IDの確認、消去、ページ書き込み、読み出し） |
| `flash_log.h` / `flash_log.c` | ログ | 16バイトの記録をためて、1ページずつ書く。CSVで出す |
| `main.c` | アプリ（試験用） | PCからの1文字コマンドで、診断・消去・記録・照合・読み出しを試す |

上の層は下の層の関数を呼ぶだけで、下の層は上の層のことを知りません。機体に載せるときは、`main.c` だけを自分のプログラムに置き換えます。

## 配線

| ICのピン | ブレッドボード（`PICO2350` = 0） | 本番の機体（`PICO2350` = 1） |
| --- | --- | --- |
| 1 CS# | GPIO3 | GPIO13 |
| 2 SO（IC → Pico） | GPIO4（SPI0 RX） | GPIO12（SPI1 RX） |
| 3 WP# | つながなくてよい | つながなくてよい |
| 4 GND | GND | GND |
| 5 SI（Pico → IC） | GPIO7（SPI0 TX） | GPIO11（SPI1 TX） |
| 6 SCK | GPIO6（SPI0 SCK） | GPIO10（SPI1 SCK） |
| 7 HOLD# | つながなくてよい | つながなくてよい |
| 8 VCC | 3.3V | 3.3V |

- ピンとSPIの速さは、`at25sf.h` の先頭で変えられます。
- WP# と HOLD# は、ICの中でプルアップされていて、浮かせたままでよいとされています（データシート Table 1）。動きが安定しないときは、3.3Vにつないでみてください。
- データシートは、CS# を10kΩでVCCにつなぐこと（プルアップ）を勧めています。基板にするときは付けてください。
- SPIの速さは、最初は1MHzにしてあります（実機でIDが読めた実績のある速さ）。`t` が通ってから10MHzなどに上げ、上げた後にもう一度 `t` を通してください。

## ビルド

`CMakeLists.txt` の `add_executable` に3つの `.c` を並べ、`hardware_spi` をリンクします（プロジェクト名は、今の `CMakeLists.txt` のものに合わせてください）。

```cmake
add_executable(プロジェクト名
    main.c
    at25sf.c
    flash_log.c
)
target_link_libraries(プロジェクト名
    pico_stdlib

```

- 今までの `Sample_AT25SF321B_SPI_Flash_Memory.c` は、`add_executable` から外してください（`main` が2つになるため）。
- `buzzer`、`pico_led_sw`、`pico_rand` は、この3つのファイルでは使っていません。

## まず動かす

シリアルモニタから、1文字ずつ送ります。最初は **`i` → `t` → `e` → `l` → `v` → `d`** の順です。

| コマンド | すること | 正常なら |
| --- | --- | --- |
| `i` | JEDEC ID とステータスを表示 | `JEDEC ID : 1F 87 01`、`SR1 : 00` |
| `t` | 自己診断（最後の4KBで、消す → 読む → 書く → 読み戻す） | `自己診断 : 合格` |
| `e` | ログの範囲（64KB分）を消去 | `消去 : OK`（約0.3秒） |
| `l` | 1msごとに1000件のダミーを記録 | `記録が終わりました : OK`、捨てたページ 0 |
| `v` | 読み戻して、書いた値と自動で照合 | `照合 : OK` |
| `d` | CSVで出す | 見出し1行と1000行、`records=1000` |
| `s` | 状態（件数、捨てたページ、かかった時間）を表示 | |
| `r` | 先頭の64バイトを16進で表示 | |
| `U` | 保護ビットを解除（`ERR_PROTECTED` が出たときだけ） | |
| `C` | チップ全体を消去（10〜30秒） | |
| `h` | コマンドの一覧 | |

`e` と `l` は組です。1回の消去につき、記録は1回です。もう一度記録するときは、`e` からやり直します。

表示の例（シミュレータでの出力です。実機では、時間の値が変わります）:


CSVをファイルにするには、`=== START DUMP ===` の次の行から `=== END DUMP ===` の前の行までを、PC側で保存します。行数が多いときは、受信した内容をファイルに保存できる端末ソフト（Tera Term のログ機能など）が便利です。

## うまくいかないとき

| 表示 | 確かめること |
| --- | --- |
| `JEDEC ID : FF FF FF` | ICから返事がありません。配線（CS、SCK、SI、SO）、ICの電源、ピンの番号 |
| `JEDEC ID : 00 00 00` | SO の線がGNDに触れていないか、ピンの番号が合っているか |
| IDが 1F 87 01 以外の値 | 値が化けています。SPIの速さを下げる、配線を短くする |
| `ERR_NO_WEL` | 06h（書き込み許可）が届いていないか、ステータスが読めていない。SI、SO、SCK、CS の配線 |
| `ERR_PROTECTED` | 保護ビットが立っている。`U` で解除してからやり直す |
| `ERR_NOT_STARTED` | 消去の命令の後に、BUSYが1になっていない。SPIの速さを下げる → 配線を短くする → HOLD# と WP# を3.3Vにつなぐ、の順に試す |
| `ERR_TIMEOUT` | BUSYが外れない。SO の配線と、ICの電源 |
| 捨てたページが 0 でない | mainのループが遅い。ループの中の `printf` や `sleep` を減らす |
| `照合 : NG` | `s` で、捨てたページと書き込みエラーを見る。どちらも0なら、`r` で先頭の値を見る |

11/13に実機で出た「全消去時間がすぐに出る」は、この表の `ERR_NOT_STARTED` にあたる状態です。`t` の [1]〜[3] のどこで止まるかで、原因を切り分けられます。

## 自分のプログラムに組み込む

`at25sf.c`、`flash_log.c` と、2つの `.h` を自分のプロジェクトに入れ、`flash_log.h` をインクルードします。

```c
#include "flash_log.h"

// 1msの制御割り込み（例）
bool control_1ms(repeating_timer_t *t)
{
    // …センサーを読む、モータを動かす…
    now_sensors_data.left_speed  = /* 左の速さ */;
    now_sensors_data.right_speed = /* 右の速さ */;
    log_put(&now_sensors_data);       // 最後に1回。RAMに詰めるだけで、数µsで終わる
    return true;
}

int main(void)
{
    stdio_init_all();
    if (log_init() != AT25SF_OK) {
        // ICと通信できていない。配線を確かめる
    }

    // 走る前（消去は秒単位でかかるので、走り出す前に済ませる）
    log_erase(60 * LOG_BYTES_PER_SEC);   // 60秒分
    log_start();

    while (/* 走行中 */) {
        flash_task();                    // 毎回呼ぶ。すぐに戻る
        // …ほかの処理（長い printf や sleep は入れない）…
    }

    log_stop();                          // 残りを書き終える

    // 後で、PCにつないで
    log_dump();                          // CSVで出す
}
```

`now_sensors_data` は `flash_log.c` の中に用意してあり、`flash_log.h` をインクルードすれば、どのファイルからでも値を入れられます。自分のプログラムに同じ名前の変数があるときは、どちらか一方にしてください。

### 守ること

1. `log_put()` を呼ぶのは1か所だけ（1msの割り込み）にする。
2. `flash_task()`、`log_erase()`、`log_stop()`、`log_dump()` は、mainから呼ぶ（割り込みの中から呼ばない）。
3. mainのループは、`flash_task()` を10ms以内の間隔で呼ぶ。間に合わないと、ページ（16件）単位で記録を捨てます。捨てた数は `log_get_stats()` の `dropped_pages` で分かります。
4. **フラッシュのSPIポートを、割り込みの中で使うデバイス（A/Dコンバータやジャイロなど）と共有しない。** mainがフラッシュに送っている途中に、割り込みが同じポートを使うと、両方の通信が壊れます。本番の設定では、フラッシュは SPI1（GPIO10〜13）を使います。
5. `log_put()` を呼ぶ割り込みと `flash_task()` は、同じコアで動かす。

### 記録できる量と時間

| 項目 | 値 |
| --- | --- |
| 1件 | 16バイト（1ページ256バイトに16件） |
| 1秒（1msごと） | 16,000バイト |
| 全体（4MB） | 262,144件 ＝ 約262秒 |
| 消去の時間 | 64KBにつき標準0.2秒、最大0.7秒。60秒分で、標準なら約3.4秒、最大なら約13秒 |
| 1ページの書き込み | 送信が約2.1ms（1MHz）または約0.2ms（10MHz）。ICの中の書き込みが標準0.4ms、最大3.4ms |

時間の値は、データシート 13.4 の標準値と最大値です。

記録の項目（`Sensors_data_t`）を変えるときは、合計を16バイトのままにして、`flash_log.c` の `log_pack`、`log_unpack`、`log_dump` の3か所も合わせて直してください。

## 確かめたこと

- **ビルド**：Pico SDK 2.3.1 と arm-none-eabi-gcc 13.2 で、Pico（RP2040）と Pico 2（RP2350）向けに、`-Wall -Wextra` の警告なしでビルドできました（シリアルは、USBとUARTの両方の設定で確かめました）。
- **動作（シミュレータ）**：フラッシュICの決まり（書く前に消す、06h が要る、BUSYの間は命令を受け付けない、ページの境界で折り返す、など）をまねたプログラムの上で、この3つの `.c` をそのまま動かしました。
  - `i` → `t` → `e` → `l` → `v` → `d` の一連の流れ
  - 1件〜4000件、4MB全体（262,144件）の記録と、1件ずつの照合
  - 記録の途中の、いろいろなタイミングでの停止
  - 上限まで記録したとき、mainのループが遅いとき、配線が外れたとき、保護ビットが立っているとき
  - 乱数でタイミングをずらした400回の繰り返し
- **まだ確かめていないこと**：実機での動作、10MHzでの動作。シミュレータは、割り込みが入るタイミングを本物ほど細かくは再現できません。

## 11/16の版（1つのファイル）から変えた所

| 変えた所 | 理由 |
| --- | --- |
| 1つのファイルを、3つの層に分けた | 役割ごとに分けると、全体が見えるようになる。機体に載せるときは `main.c` だけを入れ替えればよい |
| IDやステータスの読み方（`send_op_read`） | 送ると読むを同時に行うと、先頭に意味のない1バイトが入る。IDが1つ後ろにずれて、照合が通らなかった |
| 消去と書き込みの前に、WELと保護ビットを確かめる。結果を `AT25SF_result_t` で返す | 「命令が届いていない」「保護されている」を、黙って通り過ぎないようにする |
| 消去の命令の直後に、BUSYになったかを確かめる | 消したつもりで消えていない、を見つける（11/13の実機の状態） |
| SPIを1MHzから始める | 実機でIDが読めた実績があるのは1MHz。`t` が通ってから上げる |
| `erase_completed_flag` をやめた | 「消去が済んだ」と「記録を始めた」の2つの意味を持っていた。`log_erase` → `log_start` の順を、関数の側で守る |
| ブザー、LED、スイッチを外した | 下の2つの層は、ピンが余っているかを気にしない。切り替えは、PCからの1文字で行う |
| ドライバから `printf` を外した | BUSYの確認のたびに表示すると、その時間だけ止まり、時間の計測も狂う |
| ダミーの値を、乱数から「固定値と連番」にした | 読み戻した値が正しいかを比べられる。`0xF0F0` は上位と下位が同じで、バイトの入れ違いに気づけないので `0x1234` にした |
| `log_put` で、値の写しを取ってから詰める | 16ビットの値を上位と下位に分けて読む間に、値が変わると混ざるため |
| `log_stop` を足した | 最後の半端なページ（16件に満たない分）を書く |
| 消去の範囲に、目印の1ページを足した | 上限まで記録しても、「ここで終わり」が分かるようにする |
| `flash_task` で、BUSYの確認と次の送信を1回で行う | mainのループが遅くても間に合う（シミュレータでは、ページを捨てずに済む1周の時間が、6msから13msに延びた。1MHzのとき） |
| リセットのオペコードは載せていない | 元の定義（`0x50`、`0x66`）は、データシートの Table 4 では 66h と 99h。使っていないので外した |

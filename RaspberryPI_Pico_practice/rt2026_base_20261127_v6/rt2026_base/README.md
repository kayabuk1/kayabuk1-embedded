# RT2026 基礎プログラム（2026-11-27 第6版）

2026年モデルのロボトレーサの、配布用の基礎プログラムです。
マイコンは、Raspberry Pi Pico（RP2040）と Raspberry Pi Pico 2（RP2350）のどちらでも動きます。配るときの設定は Pico です。
ピンは、ロボット仕様書（20261122）の表1-5に合わせてあります。
機体の基板が無いときの確認用に、教育用の実験基板（PICO-BOARD-V1）でも動かせます（15章）。

**機体の基板では、まだ動かしていません。** 教育用の実験基板（Pico）では、スイッチ、ブザー、LED、つまみでの左エンコーダ、
フラッシュメモリの記録を確かめました（12章）。
機体の基板では、5章の順番で、部品を1つずつ確かめてから走らせてください。

## 1. 変わった所

### 第5版から第6版（11/27。機体の基板と回路図、先生のジャイロのドライバを受けて）

- **センサーの並びを、回路図（20261124）に合わせました**（`board.h` の `SENSOR_ADC_CH`）。
  第5版は「CH0〜CH7 が sensor[0]〜[7]」でした。機体の基板は、CH0 がスタート／ゴールのマーカー、CH1〜CH6 がラインセンサー、
  CH7 がコーナーのマーカーです。第5版のままだと、マーカーをラインセンサーとして読みます（16章）。
- **ジャイロを、先生のドライバ（`l3gd20/`）に入れ替えました**。Z軸の2バイトを、1回の通信で読みます。同級生の `l3gd20h/` は外しました。
- **ジャイロは、返事があれば、毎回読んで記録に入れます**。走行の制御に使うかどうかだけを、`USE_GYRO` で決めます（既定は 0 = 記録だけ）。
- **ジャイロのオフセット**（止まっているときの値）を、走行の前の1秒で、必ず測ります。前半の 0.5秒は、スイッチを押した手の揺れが
  収まるのを待ち、後半の 0.5秒の平均を使います。値は、走行が終わった時と `s` で表示します。
- **角度**を、プログラムの中で計算します（角速度 × 0.001秒 を足し合わせた値）。動作確認メニューの `8` と、走行が終わった時に表示します。
- **記録の数字を、四捨五入にしました**。第5版までは、小数を 0 に近い方へ切り捨てていました（8章）。
- **LED0 の向き**（`board.h` の `LED0_ON_LEVEL`）を足しました。機体の基板の LED0 は、L で点きます。
- 「走行ログ ビューア」に、角度のグラフを足しました。
- 実験基板の設定のとき、`s` の電源電圧を「測っていません」と表示します。

### 第4版から第5版（11/25 午後。「当面は Pico で走らせる」という先生の話を受けて）

- **「どの基板か」と「どのマイコンか」を、別の設定に分けました**（3章）。
  第4版は、Pico 向けにビルドすると、自動で実験基板のピンになりました。機体の基板に Pico を載せる場合に合わないので、やめました。
  - どのマイコンか：`CMakeLists.txt` の `PICO_BOARD`（`pico` か `pico2`）。既定を `pico` にしました。
  - どの基板か：`board.h` の `BOARD_EDU`（0 = 機体の基板、1 = 実験基板）。既定は 0 です。
  - 機体の基板のピンの番号は、Pico でも Pico 2 でも同じです（エンコーダは GP6〜GP9、フラッシュメモリは GP2〜GP5）。
  - フラッシュメモリのピンは、`BOARD_EDU` で切り替わります。前に使っていた `PICO2350` は、使わなくなりました。
- **起動のメッセージ**に、「基板の設定」と「マイコン」の2行を出します。どの組み合わせでビルドした物かが、画面で分かります。
- **動作確認メニューの `9` に `c` を足しました。** フラッシュメモリの全体（4MB）を読んで、消えているか（どのバイトも FF か）を調べます。
  全消去が1秒前後で終わるので、消去できたかを、時間ではなく中身で確かめるためです（6章）。
- **1msの割り込みにかかった時間**を測って、`s`（状態）と、走行が終わった時に表示します。
  Pico は小数の計算が遅いので、1ms に収まっているかを、実機で確かめるためです（6章）。

### 第3版から第4版（11/25 午後。教育用の実験基板で試した結果を受けて）

- **教育用の実験基板の設定を入れました**（15章）。Pico 向けにビルドすると、ピンが実験基板用に切り替わります。
  切り替えは `CMakeLists.txt` の `PICO_BOARD` の1か所だけで、`board.h` を手で書き換える必要はありません。

- **動作確認メニューの中でスイッチを押す**と、「`q` で戻ってから押してください」と表示します。メニューの中では、スイッチでの操作（走行、キャリブレーション、全消去）は働きません。
- **全消去の時間の表示**を「長いときは30秒」に変えました。実機では 0.6秒で終わりました（12章）。

## 3. ビルドと書き込み

1. VS Code の Raspberry Pi Pico 拡張機能で、ボードを、基板に載せるマイコン（**Pico** か **Pico 2**）にして、新しいプロジェクトを作る。
2. このフォルダの中身を、プロジェクトのフォルダにコピーする。
3. `CMakeLists.txt` は、拡張機能が作った物の先頭（「DO NOT EDIT」の部分）を残し、
   `project(...)` から下を、このフォルダの `CMakeLists.txt` の `project(...)` から下に置き換える。
   プロジェクトの名前を変えたときは、`rt2026_base` を全部その名前に直す。
4. ビルドして、`.uf2` を書き込む。

決める所は、2か所です。この2つは、互いに関係しません。

| 決めること | 場所 | 値 |
|---|---|---|
| どのマイコンを載せるか | `CMakeLists.txt` の `PICO_BOARD` | `pico`（既定）か `pico2` |
| どの基板で動かすか | `board.h` の `BOARD_EDU` | 0 = 機体の基板（既定）、1 = 教育用の実験基板 |

| 使い方 | `PICO_BOARD` | `BOARD_EDU` | ビルド済みの物（`prebuilt/`） |
|---|---|---|---|
| 機体の基板に Pico を載せる（配るときの設定） | `pico` | 0 | `rt2026_base_robot_pico.uf2` |
| 機体の基板に Pico 2 を載せる | `pico2` | 0 | `rt2026_base_robot_pico2.uf2` |
| 教育用の実験基板（Pico）で試す | `pico` | 1 | `rt2026_base_edu_pico.uf2` |

- Pico と Pico 2 は、ピンの並びが同じです。マイコンを変えても、`board.h` は変えません。
- マイコンを変えるときは、`PICO_BOARD` の行を変えて、ビルドのフォルダ（`build`）を消してから、ビルドし直します。
  拡張機能に「Switch Board」の操作があれば、それでも変えられます。プログラムの中には、ほかに変える所はありません。
- どの組み合わせで動いているかは、シリアルの画面をつないだ時の「基板の設定 : 」「マイコン : 」の2行で分かります。
- Pico に Pico 2 向けの `.uf2` は書き込めません（逆も同じです）。ドライブにコピーしても、プログラムが始まりません。

ビルドでつまずいたときは、`prebuilt/` の `.uf2` を先に書き込めば、5章の動作確認だけは進められます
（BOOTSEL ボタンを押しながらUSBをつなぎ、出てきたドライブに、このファイルをコピーします）。
`board.h` や `params.h` を変えた後は、自分でビルドした `.uf2` を使ってください。

## 4. 操作

| 操作 | 動き |
|---|---|
| スイッチ0を短く押す | 走行開始。1秒後に動き出す。キャリブレーションがまだのとき、電池の電圧が低いときは、走らない |
| スイッチ0を1秒長押し | キャリブレーションを始める。機体をラインの上で左右に動かし、スイッチ0をもう一度押すと終わる（押さなくても6秒で終わる） |
| スイッチ1を2秒長押し | フラッシュメモリの全消去（データシートでは標準10秒、最大30秒。11/25 の実機では 0.6〜1.4秒）。始めと終わりに、長いブザー |
| 走行中に、どちらかのスイッチを押す | 停止（動き出す前の1秒の間も同じ） |
| USBシリアルの `1`〜`5` | その番号の走行の記録を、CSVで出す |
| USBシリアルの `d` | いちばん新しい走行の記録を、CSVで出す |
| USBシリアルの `s` | 状態を表示する（電源電圧、キャリブレーション、1msの割り込みにかかった時間、走行ごとの記録の件数） |
| USBシリアルの `h` | 基板の動作確認メニュー |
| USBシリアルの `E`、続けて `y` | フラッシュメモリの全消去 |
| USBシリアルの `?` | 操作の説明 |

スイッチとUSBシリアルの操作は、待ちの状態（LED0 が0.5秒ごとに点滅）のときだけ受け付けます。
動作確認メニュー（`h`）を開いている間は、スイッチでの操作は働きません。`q` で戻ってから押します。

### 走行の流れ

機体を、スタートのマーカーの手前に置きます。スイッチ0を押すと、1秒後に加速しながら走り出し、
右側のマーカーの1個目（スタート）を過ぎ、2個目（ゴール）を過ぎたら、減速して止まります。
交差（左右のマーカーセンサーが同時に白を見る所）は、マーカーとして数えません。

走行は、次のどれかで止まります。

| 止まり方 | 条件 |
|---|---|
| ゴールのマーカーで止まった | 右側のマーカーの2個目を過ぎた |
| スイッチで止めた | 走行中に、どちらかのスイッチを押した |
| ラインを見失って止まった | ラインセンサー6個とも白が見えない状態が、0.3秒続いた |
| 車輪が回っていないか、逆に回っている | duty が10%より大きいのに、その車輪が止まったまま0.5秒、または後ろ向きに回ったまま0.1秒 |
| 時間切れ | 走り始めてから120秒 |

どうしても止まらないときは、基板のリセットのスイッチを押します。マイコンのピンが全部入力に戻り、モーターが止まります。

### 記録

- 1msごとに1件（16バイト）を記録します。走行1は 64,512件（64.5秒）、走行2〜5は 48,896件（48.9秒）まで入ります。
  いっぱいになったら、記録だけを止めて、走行は続けます。
- スイッチ0を押すたびに、走行1、走行2 … の順に、次の場所へ記録します。
- 5回分を使い切った後と、全消去がまだのときは、**記録なしで走ります**（始まりのブザーが、低い音で2回になります）。
- もう一度記録するには、必要な走行を `1`〜`5` で読み出してから、全消去をします。
- 途中で電源が切れても、そこまでに書いたページ（16件ごと）は残ります。その回は「使った」と数えます。
- 動作確認メニューの `9` → `y`（フラッシュの確認）も、走行1回分の場所を使います。

### ブザーとLED

| 鳴り方 | 意味 |
|---|---|
| 起動時、高い音で短く2回 | フラッシュメモリと通信できた |
| 起動時、低い音で長く1回 | フラッシュメモリと通信できていない（記録なしで走れます） |
| 起動時、低い音で8回 | 前回、プログラムが途中で止まり、見張りのタイマーがリセットした（今回は、見張りのタイマーを使わずに動く） |
| スイッチ0を押した直後、高い音で短く1回 | 走行開始（記録あり） |
| スイッチ0を押した直後、低い音で短く2回 | 走行開始（記録なし） |
| スイッチ0を押した直後、低い音で短く4回 | キャリブレーションがまだなので、走らない |
| スイッチ0を押した直後、低い音で短く6回 | 電池の電圧が低いので、走らない |
| スイッチ0を押して1秒後、短く1回 | 動き出す |
| キャリブレーションの後、高い音で短く2回 | 成功 |
| キャリブレーションの後、低い音で長く1回 | 失敗（白と黒の差が小さいセンサーがある）。前の値に戻る |
| 走行中、低い音で短く1回 | スタート、ゴールのマーカーを過ぎた |
| 走行中、低い音で長く1回 | 安全のための停止 |
| 走行の後、高い音で短く2回 | 記録に欠けが無い（記録なしで走ったときも同じ） |
| 走行の後、低い音で長く | 記録に欠けがある |
| 全消去の始めに長く、終わりに高い音で長く | 全消去が終わった |
| 全消去の後、低い音で8回 | 全消去に失敗した |

| LED | 点き方 | 意味 |
|---|---|---|
| Picoの基板の上のLED | 0.5秒ごとに点滅 | 1msの割り込みが動いている |
| LED0（GP17） | 0.5秒ごとに点滅 | 待ち |
| LED0（GP17） | 速い点滅 | キャリブレーション中、全消去中 |
| LED0（GP17） | 点きっぱなし | 走行中（動き出す前の1秒を含む） |

## 5. 新しい基板で最初に確かめる順番

USBをつなぎ、シリアルの画面で `h` を押して、順に進めます。車輪が付いているときは、機体を台に載せて、**車輪を浮かせておきます**。
1つでも合わない所があれば、そこで止めて、`board.h` を直してビルドし直してから、先へ進みます。

| 順 | 操作 | 正しいときの様子 | 合わないときに直す所 |
|---|---|---|---|
| 0 | 電源を入れて、シリアルの画面を開く | Picoの基板の上のLEDが点滅。「基板の設定 : 機体の基板」「マイコン : 」（載せた物と同じ名前）「フラッシュメモリ : 通信OK」「ジャイロ : 返事あり」と出る | `BOARD_EDU`、`PICO_BOARD`（3章） |
| 1 | `1` スイッチとLED | 押している間だけ 1 になる。LED0 が、Picoの基板の上のLEDと同じ調子で点滅する | `SW_PRESSED_LEVEL`、`LED0_ON_LEVEL` |
| 2 | `2` ブザー | ド・ミ・ソと鳴る | `PIN_BUZZER` |
| 3 | `3` ラインセンサー | 白と黒で、8個とも raw が変わる。白の上で小さく、黒の上で大きい | `LINE_LED_ON_LEVEL` |
| 4 | `3` の続き | センサーを1個ずつラインに載せる。右端のラインセンサーで、画面のいちばん左の列（sensor[0]）が変わる。右のマーカーで [6]、左のマーカーで [7] が変わる。機体をラインの右にずらすと、「ずれ」が正になる | `SENSOR_ADC_CH`、`LINE_DISP_SIGN` |
| 5 | `4` 電源電圧 | テスターで測った電池の電圧と、ほぼ同じ値になる | `VBAT_R_TOP`、`VBAT_R_BOTTOM` |
| 6 | `8` ジャイロ | 「WHO_AM_I = D4」（L3GD20H なら D7）。手を離して約1秒でオフセットが出る。振れ幅が 2.0 より小さい。左に90度回して止めると、角度が約 +90 | `GYRO_Z_SIGN`、配線（CS=GP13） |
| 7 | `9` → `e`（全消去）、続けて `9` → `y` | 「結果 : 合格」 | 配線（SCK=GP2、MOSI=GP3、MISO=GP4、CS=GP5） |
| 8 | `5` エンコーダ | モーターの軸（車輪）を手で回すと、回した側の数が変わる。車輪が付いていれば、前進の向きで数が増え、タイヤ1回転で840 | `ENC_L_SIGN`、`ENC_R_SIGN` |
| 9 | `6`、`7`、`b` モーター | 回した側のモーターだけが回り、その側の数が**増える**。車輪が付いていれば、前進の向きに回る | `MOTOR_L_SIGN`、`MOTOR_R_SIGN` |
| 10 | `q` で戻り、スイッチ0を1秒長押し | 機体を左右に動かして、もう一度押すと「キャリブレーションが終わりました : 成功」 | 画面に出たセンサーを、白と黒の両方に通す |
| 11 | `s` | 「1msの割り込みにかかった時間」の最大が 800 us より小さい | 6章 |
| 12 | 走行 | `RUN_SPEED_MPS` を 0.3 にして、短い直線から試す。終わった時に、オフセットと、回った角度が出る | 6章の表、`params.h` |

補足です。

- 順番3と4の画面は、左から sensor[0]（右端）〜[5]（左端）、[6]（スタート・ゴール側のマーカー）、[7]（コーナー側のマーカー）です。
  「白黒」の8桁だけは、左から sensor[7]、[6]、[5] … [0] の順です。
- 順番4で、右端のラインセンサーを載せたときに sensor[2] が変わるなら、`SENSOR_ADC_CH` を `{3, 2, 1, 6, 5, 4, 0, 7}` にします（16章）。
- 順番7の `9` → `y` は、全消去の後でないと「記録を始められませんでした」と出ます。先に `e` をします。
- 順番9で「数が減る」ときは、モーターとエンコーダの向きが合っていません。`MOTOR_x_SIGN` か `ENC_x_SIGN` の、どちらか片方を逆にします。
  どちらを逆にするかは、車輪を付けて、前進の向きが分かってから決めます。

### 車体と車輪が無いときの確かめ方（台の上での走行）

モーターとエンコーダだけが付いていれば、順番9までの後、次の形で、マーカーの判定と記録を確かめられます。

1. モーターを、軸が何にも触れないように置きます。回る軸と配線に、手を近づけません。
2. 基板を手で持って、センサーをコースのラインの上にかざします。順番10のキャリブレーションをします。
3. スイッチ0を短く押して、1秒は動かさずに待ちます。モーターが回り始めます。
4. 基板を、ラインに沿って手で動かします。右のマーカーの1個目でブザーが鳴ります（スタート）。
   交差では鳴りません。右のマーカーの2個目でブザーが鳴り、減速して止まります（ゴール）。
5. `d` で記録を出して、「走行ログ ビューア」に貼ります。

センサーをラインから 0.3秒より長く外すと、「ラインを見失って止まった」になります。車輪に重さがかかっていないので、
記録の速さとデューティの波形は、走るときとは違います。マーカーの判定、ジャイロ、記録の確認として使います。

## 7. 走りの調整

| 値 | 既定 | 意味 |
|---|---|---|
| `RUN_SPEED_MPS`（`params.h`） | 0.5 | 定常の速さ [m/s]。先生のサンプルは 0.7 |
| `RUN_ACCEL_MPS2`、`RUN_DECEL_MPS2`（`params.h`） | 1.0 | 加速度と減速度 [m/s²]。先生のサンプルは 2.0 |
| `OMEGA_GAIN`（`params.h`） | 1.0 | ずれから決めた目標の角速度に掛ける倍率 |
| `DUTY_LIMIT`（`params.h`） | 0.5 | モーターに出す duty の上限。速さを上げるときは、一緒に上げる |
| `USE_GYRO`（`params.h`） | 0 | 1 にすると、ジャイロで読んだ角速度を、旋回の補正に使う（実機では未確認）。0 でも、ジャイロは記録に入ります |
| `K_SPEED_ERROR`（`encoded_geared_motor.h`） | 5.0 | 車輪の速さの誤差に掛ける値 [V/(m/s)]（仕様書 4.1.5） |
| `K_BACK_EMF_L`、`K_BACK_EMF_R`（`encoded_geared_motor.h`） | 0.00382 | 逆起電力定数 [V/(rad/s)]。機体ごとに合わせる |
| `K_YAW`（`encoded_geared_motor.h`） | 0.02 | 角速度の誤差に掛ける値 [V/(rad/s)]（仕様書 4.1.5） |

ゴールのマーカーを過ぎてから止まるまでの距離は、およそ「速さ × 速さ ÷（2 × 減速度）」です
（例：0.5m/s、1.0m/s² なら 0.125m。1.0m/s、1.0m/s² なら 0.5m）。速さを上げるときは、`RUN_DECEL_MPS2` も上げます。

この章の表の数字は、どれも**PCの上の模型で走らせた結果**です。モーターやタイヤの実際の特性は入っていないので、実機でも同じ数字になるとは言えません。
「どの値を、どちらに動かすと、どうなるか」の向きを知るための物として見てください。
数字は、ラインからの最大のずれです。コースAは半径250〜300mmのカーブと交差、コースCは半径100〜150mmのカーブとS字です。

### duty の計算：仕様書の式と、担当の方の元の計算

担当の方の `p_control()` は、逆起電力のぶんの電圧と、ジャイロの補正が、仕様書 4.1.5 の式のとおりです。
速さの誤差の項だけ、仕様書と違っていました。

| | 速さの誤差 | 掛ける値 |
|---|---|---|
| 仕様書 4.1.5 | （その車輪の目標の速さ）－（その車輪の今の速さ） | 5 |
| 担当の方の元の計算 | （車体の目標の速さ）－（その車輪の今の速さ） | 0.3 |

元の計算は、カーブでも左右の車輪を同じ速さに近づける向きに働きます。掛ける値を 5 に上げると、その働きが強くなり、曲がれなくなります
（例：0.5m/s で半径100mmのカーブでは、内側の車輪の目標は 0.21m/s、外側は 0.79m/s ですが、両方を 0.5m/s に近づけようとします）。
模型で比べた結果です。摩擦は、担当の方のヘッダにコメントで残っている静摩擦の値（12% と 18%）を、5Vでの電圧（0.6V と 0.9V）と読んで入れました（この読み方は推測です）。

| 設定（`SPEED_ERROR_PER_WHEEL`、`K_SPEED_ERROR`） | 摩擦なし：A / C | 摩擦あり：A / C | 摩擦ありのときの速さ（目標 0.5m/s） |
|---|---|---|---|
| 仕様書の式（1、5.0）**既定** | 5.5mm / 18.6mm | 6.4mm / 19.7mm | 0.40m/s |
| 元の計算（0、0.3） | 14.8mm / 43.1mm | 18.3mm / 42.9mm | 0.26m/s |
| 元の計算のまま、値だけ 5.0（0、5.0） | 26.0mm / ラインを外れて停止 | 26.5mm / ラインを外れて停止 | 0.40m/s |
| 式だけ仕様書（1、0.3） | 9.2mm / 30.8mm | 17.3mm / 31.1mm | 0.26m/s |

この結果から、既定を仕様書の式にしました。元の計算に戻すときは、`encoded_geared_motor.h` の
`SPEED_ERROR_PER_WHEEL` を 0、`K_SPEED_ERROR` を 0.3f にします（2行）。

## 8. 記録の読み方

`1`〜`5` か `d` を押すと、次の形で出ます。`=== START DUMP ===` から `=== END DUMP ===` までがCSVです。
「走行ログ ビューア」に貼るか、行を保存して表計算ソフトで開きます。

| 列 | 中身 |
|---|---|
| `sensor_displacement` | ラインからのずれ（-100〜+100。機体がラインの右にあるときが正） |
| `sensor_binary` | センサー8個の白黒（ビット0 = sensor[0] … ビット7 = sensor[7]。白が1） |
| `target_speed`、`left_speed`、`right_speed` | 目標の速さ、左右の車輪の速さ [mm/s] |
| `left_motor_duty`、`right_motor_duty` | 左右の duty [%] |
| `target_angular_velocity` | 目標の角速度 [deg/s]（左に曲がるときが正） |
| `now_angular_velocity` | ジャイロで読んだ角速度 [deg/s]（オフセットを引いた値。左回りが正）。`USE_GYRO` が 0 でも入ります。ジャイロの返事が無い基板では、左右の車輪の速さの差から計算した値 |
| `vcc_mv` | 電源電圧 [mV] |

- **角度の出し方**：記録は1msごとなので、`now_angular_velocity` × 0.001 を、最初の行から足し合わせると、角度 [度] になります。
  例：90 deg/s の行が1000行続くと、90度です。「走行ログ ビューア」は、この計算をして、角度のグラフを出します。
  機体の中でも同じ計算をしていて、走行が終わった時に「走行中に回った角度」として表示します（こちらは、整数に丸める前の値を使います）。
- **数字の丸め方**：第6版から、四捨五入です。第5版までは、小数を 0 に近い方へ切り捨てていました（2.7 → 2、-2.7 → -2）。
  切り捨てのままだと、曲がっている間の角速度が、平均で約0.5 deg/s 小さく記録されて、足し合わせた角度がずれます。
- 角速度は 1 deg/s 単位の記録です。同じ速さで長く曲がり続けると、丸めた分（最大 0.5 deg/s）が角度に残ります。
  もっと細かく記録したいときは、単位を 0.1 deg/s にする方法があります（記録の大きさは変わりません。先生に確認してから）。

## 10. 仕様書の中で食い違っていた所（先生に確認）

1. 7ページの図は「フラッシュ＝SPI1、A/D変換とジャイロ＝SPI0」、8ページのピン表は逆。

## 14. 担当の方のファイルで変えた所と、気づいた点

良かった点を先に書きます。ピンと機体の定数（車輪の半径、車輪の間の距離、1mあたりのエンコーダの数、減速比）は、

10msぶんの数の合計から速さを出す作りも、そのまま使っています。

### 変えた所（ファイルの中にも、同じ内容をコメントで書いてあります）

ジャイロ（`l3gd20/`。先生の 11/27 の実演のプログラム）

1. `l3gd20.h`：ピンの番号（10、11、12、13）を、`board.h` の名前に置き換えた。機体の基板では、元と同じ番号です。
   教育用の実験基板の設定のときに、別のピンにするためです。変えたのは、ここだけです。

使い方で変えた所（先生のファイルは変えていません）：実演のプログラムは、main から `l3gd20_read_gyro()` を呼んでいました。
基礎プログラムでは、同じ SPI1 を1msの割り込みがA/D変換ICに使うので、ジャイロも割り込みの中で `l3gd20_read_raw()` を呼びます。
main から呼ぶ形の `l3gd20_calibrate()`（200回、約2.2秒）は使わず、オフセットは `control.c` が、走行の前の1秒で測ります。
起動時に `l3gd20_read_reg()` で WHO_AM_I を読み、返事が正しいときだけ、ジャイロを読みます。

モーターとエンコーダ（`encoded_geared_motor/`）

- A. `motor_data_input()`：エンコーダの数に、`board.h` の `ENC_L_SIGN` / `ENC_R_SIGN` を掛ける。
- B. `motor_set()`：duty に `MOTOR_L_SIGN` / `MOTOR_R_SIGN` を掛ける。あわせて、IN1 と IN2 の役割を、仕様書 3.6 の表
  （duty が正のとき IN1=H、IN2=PWM）に合わせた。元は、duty が正のとき IN1=PWM、IN2=H で、表の「duty が負」の行と同じ出し方でした。
- C. `motor_free()` を足した（IN1 と IN2 を両方L）。ブレーキのままだと、車輪を手で回しにくく、エンコーダの確認がしづらいため。
- D. `K_BACK_EMF_R`：0.00332 → 0.00382。配布用なので、既定は左右とも仕様書の値にした。
- E. `SPEED_ERROR_PER_WHEEL` を足した。速さの誤差の計算を、仕様書の式と、元の計算とで切り替える（7章）。
- F. `K_SPEED_ERROR`：0.3 → 5.0（仕様書の値）。E とセット。
- G. `ENCODE_INPUT_PIN_L` / `R`：教育用の実験基板の設定のときだけ、16 と 13 にする（15章）。機体の基板のときの 6 と 8 は、元のまま。

基礎プログラムからの呼び方：1msの割り込みの最初で `motor_control()` を左右1回ずつ呼び、走行中だけ、
その duty を上限（`DUTY_LIMIT`）に収めて `motor_set()` に渡しています。電源電圧は、毎回、測った値を `Vbattery` に入れています。

### 気づいた点（プログラムは変えていません。担当の方に伝える候補です）

- ジャイロ：`CTRL_REG1` が 0x0C なので、値の更新は1秒に95回（約10.5msに1回）です。1msごとに読むと、同じ値が約10回続きます。
  記録と角度には足ります。旋回の補正に使うなら、1秒に760回の設定（上位2ビットを 11 にする）が候補です。
- ジャイロ：`l3gd20.h` のコメントは「CTRL_REG1=0x0F」ですが、`l3gd20.c` は 0x0C（Z軸だけ有効）を書いています。動きには影響しません。
- ジャイロ：下位と上位の2バイトを1回の通信で読むので、別々に読むより、上下が別の回の値になりにくいです。
  `CTRL_REG4` を 0x20 から 0xA0 にする（BDU のビットを立てる）と、読んでいる途中の更新も止められます。
- モーター：`stiction_compensation_calc()` の後退の側。`k_motor_back` に負の値（コメントにある -7 など）を入れると、
  `output < k_motor_back` が成り立たず、下の式で duty の符号が合わなくなります。今は 0 なので、影響はありません。
- モーター：`motor_driver_init()` の `slice_num_L` と `slice_num_R` は、使われていません（ビルドの警告2件の元です）。
- モーター：加速度のぶんの電圧（仕様書 4.1.7）は、まだ `p_control()` に入っていません（`accel` は、基礎プログラムから渡しています）。

## 15. 教育用の実験基板（PICO-BOARD-V1）で試すとき

機体の基板が無いときの確認用です。配る物の既定は、機体の基板の設定です。実験基板で試す人だけが、次の切り替えをします。

### 切り替え方

`board.h` の `#define BOARD_EDU 0` を `#define BOARD_EDU 1` にして、ビルドし直します。変える所は、この1行だけです。
ピン（`board.h`）、フラッシュメモリのピン（`at25sf/at25sf.h`）、エンコーダのピン（`encoded_geared_motor.h`）が、一緒に切り替わります。
`CMakeLists.txt` の `PICO_BOARD` は、実験基板に載っているマイコン（Pico なら `pico`）のままにします。
機体の基板に戻すときは、`BOARD_EDU` を 0 に戻して、ビルドし直します。

シリアルの画面を開いたときに「基板の設定 : 教育用の実験基板とブレッドボード（board.h の BOARD_EDU が 1）」と出れば、切り替わっています。

機体の基板の番号のままにできない理由は、2つです。

- GP10〜GP12 は、実験基板のLEDにだけつながっていて、ヘッダに出ていません。
- GP16 と GP17 は、ロータリーエンコーダにつながっています。プログラムがこのピンを出力にすると、つまみを回して接点が閉じたときに、出力がGNDへ直接つながります。

機体の基板用の物は、GP13 と GP14（実験基板ではタクトスイッチ）と、GP17（実験基板ではつまみ）を、出力に使います。
実験基板でスイッチを押したり、つまみを回したりすると、その出力がGNDへ直接つながります。
書き込んでしまったときは、スイッチとつまみに触らずに、`BOARD_EDU` が 1 の物を書き込み直します。

- 推測が残っているのは、ラインセンサーの左右の順番です。「PT_R1 がいちばん右、PT_L1 がいちばん左」と見て並べました
  （コネクタ CN2 の並びが L1、L2、L3、R3、R2、R1 のため）。5章の順番4で確かめます。
- ブザーは、GP22 を H のままにすると、電池から 1kΩ に電流（7.4V なら約7mA）が流れ続けます。GP22 から流れる電流は、
  トランジスタの入力の分だけで、1mA より小さいです。プログラムは、鳴らさない間、GP22 を L にしています。

## 2. C言語組み込み設計の疑問解決マニュアル（指導内容の本質的理解）

指導者（先生）から提示された「グローバル変数の抑制」「`static`の付与」「ポインタ渡しの推奨」「割込み時の例外処理」について、その背後にある技術的理由と設計思想を詳しく解説します。

### (1) なぜグローバル変数を極力作ってはいけないのか？

#### 理由
1. **結合度（Coupling）の増大と可読性の低下**:
   プログラム内のどこからでもアクセス・書き換えができるグローバル変数があると、「いつ・誰が・どの関数でこの値を変更したのか」を追跡することが困難になります。
2. **再入可能性（Reentrancy）とマルチスレッド/割込み不具合の危険性**:
   複数の関数や割込みハンドラが同時に同じグローバル変数を読み書きすると、データ競合（レースコンディション）が発生し、不可解なバグの原因になります。

#### Javaのオブジェクト指向との対比
Javaでフィールドを `private` に設定し、ゲッター/セッター経由で操作させる概念と**全く同じ思想**です。
C言語には `private` キーワードが存在しないため、**「特定の `.c` ファイル内に変数を隠蔽し、操作用関数（`led_buffer_set_pixel` 等）を通してのみアクセスを許可する」** ことでカプセル化（Encapsulation）を実現します。

---

### (2) なぜ `static` を付けるべきなのか？

C言語におけるファイルスコープ（関数の外）の `static` キーワードは、**「内部リンケージ（Internal Linkage）」** を指定することを意味します。

```c
// 他の .c ファイルからは見えない、このファイル専用の隠蔽されたバッファ
static LEDBuffer g_led_matrix = { .bytes = {0} };
```

#### 理由
1. **名前衝突（Symbol Collision）の防止**:
   大規模開発で別のライブラリ（例: 液晶用ライブラリ）を結合した際、あちらでも `buffer` というグローバル変数が使われていると、コンパイル・リンクエラーになります。`static` を付けることで、その変数や関数のスコープを現在の `.c` ファイル内に限定できます。
2. **カプセル化の強化**:
   `main.c` などの外部ファイルから `g_led_matrix` を直接勝手に書き換えられるのを防ぎ、必ず提供された API (`led_buffer_...`) を経由させることができます。

---

### (3) なぜ値渡しではなくポインタ渡し `f(&a)` を使うべきなのか？

関数の引数に `f(&a)` のようにアドレス（ポインタ）を渡すスタイルには、明確な2つのメリットがあります。

#### 理由1：メモリコピーコストと処理速度（パフォーマンス）
C言語で構造体や配列を「値渡し（`f(a)`）」すると、関数の呼び出し時に**構造体全体のメモリがスタック領域にそのままコピー**されます。
* 値渡し: 8バイト〜数10バイトの全データをメモリコピーする（遅い・スタック消費）
* ポインタ渡し (`f(&a)`): わずか 4バイト（32ビットポインタ）のアドレス情報のみを渡す（高速・低負荷）

#### 理由2：元データの直接書き換えと変更意図の明示
呼び出し先の関数で元のバッファや変数の内容を直接変更したい場合、値渡しではコピーが渡されるため元の変数は変わりません。ポインタを渡すことで、呼び出し先から呼び出し元のメモリを直接更新できます。また、呼び出し側で `&a` と書くことで**「この関数内で変数 `a` の中身が変更される可能性がある」**という意図をコード上で明確に表現できます。

---

### (4) なぜ割り込み（ISR）ではグローバル変数が許容・推奨されるのか？

割り込み処理（ISR: Interrupt Service Routine）とは、タイマーやボタン押下などのハードウェアイベントによって、実行中のプログラムを中断して即座に呼び出される特殊な関数です。

#### 理由
1. **割込みハンドラは引数を受け取れないという制約**:
   ハードウェア（CPU）によって自動的に呼び出される割込み関数（例: タイマー割込み）は、ソフトウェアから引数（`f(&a)`）を渡すことができません。
2. **状態共有の唯一の手段**:
   割込み関数内でLEDの描画スキャンを行ったりバッファを参照したりするには、関数間でデータを引き継ぐ手段が**「ファイルスコープの `static` グローバル変数」**以外に存在しないためです。

※割り込みで使用するグローバル変数は、コンパイラによる最適化（消去）を防ぐために **`volatile` 修飾子** を付与し、アトミック操作に配慮するのが定石です。

## 3. 追加・機能拡張されたバッファ操作モジュールの詳細解説

リファクタリング版ソースコード (`Sample_matrixLED03_refactored.c`) で実装された追加機能の仕組みと数学的アルゴリズムを解説します。

---

### (1) ３．シフト（移動）バッファ操作

#### ① `led_buffer_shift_rows(int offset)` (上下移動)
* **正の値 (+offset)**: 上シフト (Y=0方向へ移動、下端Y=7側に0を補填)
* **負の値 (-offset)**: 下シフト (Y=7方向へ移動、上端Y=0側に0を補填)

```c
void led_buffer_shift_rows(int offset) {
    if (offset == 0) return;

    if (offset > 0) { // 上シフト
        for (int y = 0; y < 8; y++) {
            if (y + offset < 8) {
                g_led_matrix.bytes[y] = g_led_matrix.bytes[y + offset];
            } else {
                g_led_matrix.bytes[y] = 0x00; // はみ出た部分は消灯
            }
        }
    } else { // 下シフト
        int abs_offset = -offset;
        for (int y = 7; y >= 0; y--) {
            if (y - abs_offset >= 0) {
                g_led_matrix.bytes[y] = g_led_matrix.bytes[y - abs_offset];
            } else {
                g_led_matrix.bytes[y] = 0x00;
            }
        }
    }
}
```

#### ② `led_buffer_shift_cols(int offset)` (左右移動)
共用体の強みを活かし、各行の8ビット数値 (`bytes[y]`) に対してビットシフト演算子 (`<<`, `>>`) を適用することで爆速で左右スライドを実現します。

* **正の値 (+offset)**: 左シフト (X0方向へ詰める ➔ `<< offset`)
* **負の値 (-offset)**: 右シフト (X7方向へ詰める ➔ `>> abs_offset`)

---

### (2) ４．演出・重ね合わせ（合成）バッファ操作

#### ① `led_buffer_draw_pattern(const uint8_t pattern[8])` (一括転写)
指定された8バイトのドット絵データ配列を、そのままフレームバッファへコピーします。

#### ② `led_buffer_overlay_pattern(const uint8_t pattern[8], uint8_t mode)` (重ね合わせ)
背景画像の上にキャラクターを重ねたり、特定部分をマスクしたりするためのビジュアル演算処理です。

* **`OVERLAY_MODE_OR` (論理和 `|=`)**: 重ね描き（元の絵を消さずに新しいパターンを追加点灯）
* **`OVERLAY_MODE_AND` (論理積 `&=`)**: マスク処理（両方で1の場所だけを残してくり抜き）
* **`OVERLAY_MODE_XOR` (排他的論理和 `^=`)**: 点滅・反転重ね（重なった部分の点灯/消灯を反転）

#### ③ `led_buffer_rotate_90(void)` (90度時計回り回転)
2次元座標転置アルゴリズムを適用し、元の座標 $(x, y)$ のピクセルを回転後の座標 $(7-y, x)$ へ再配置することで、画面全体を90度右回転させます。

```c
void led_buffer_rotate_90(void) {
    LEDBuffer temp = { .bytes = {0} };
    for (uint8_t y = 0; y < 8; y++) {
        for (uint8_t x = 0; x < 8; x++) {
            bool bit = (g_led_matrix.bytes[y] >> x) & 0x01;
            if (bit) {
                temp.bytes[x] |= (1 << (7 - y)); // (x,y) ➔ (7-y, x) への行列変換
            }
        }
    }
    g_led_matrix = temp; // 回転後のバッファで上書き
}
```

## 4. テスト関数とタイマー定数の比較・解説

### (1) 1ドットずつ点灯するアニメーションの2つの形態

質問にありました「1ドットずつ表示できない感じ？」という疑問に対し、用途に応じた2種類のアニメーションテストを用意しました。

```c
// ① 累積打点テスト（点灯ドットが消えずに次々と増えていき、最終的に全点灯になる）
void test_accumulate_dots_animation(void) {
    led_buffer_clear_all(); // 最初に1回だけクリア
    for (uint8_t y = 0; y < 8; y++) {
        for (uint8_t x = 0; x < 8; x++) {
            led_buffer_set_pixel(x, y, ON); // ONを追加
            led_render_frame(50);           // 50ms保持
        }
    }
}

// ② 単一1ドット掃引テスト（直前のドットは消え、1つの点だけが画面を走る）
void test_single_dot_sweep_animation(void) {
    for (uint8_t y = 0; y < 8; y++) {
        for (uint8_t x = 0; x < 8; x++) {
            led_buffer_clear_all();         // 毎回クリア！
            led_buffer_set_pixel(x, y, ON); // 1点だけON
            led_render_frame(50);           // 50ms保持
        }
    }
}
```

### (2) `step_delay_ms` (36ms) と `DEFAULT_RENDER_DURATION_MS` (10,000ms) の違い

なぜスクロール表示の時に `DEFAULT_RENDER_DURATION_MS`（10秒）ではなく `36ms` という別の定数（`DEFAULT_SCROLL_STEP_MS`）を使うのかについての解説です。

* **`DEFAULT_RENDER_DURATION_MS` (10,000ms = 10秒)**:
  「完成した1枚の静止画（1フレーム）」を画面にじっと動かさず表示し続けるための静止時間です。
* **`DEFAULT_SCROLL_STEP_MS` (36ms)**:
  文字を1ピクセル横に動かした際、**「次の1ピクセルを動かすまでの移動待ち時間」** です。
  もしスクロールのコマ送り時間として 10秒 を渡してしまうと、「1ピクセル進むのに10秒待たされる」という超極端なコマ送りになってしまいます。人間の目が滑らかなスクロールとして認識できる最適な移動速度が **約 30 〜 50ms（1秒間に約20〜30ピクセル移動）** であるため、`36ms` という専用の定数を定義して使用しています。

## 5. メイン関数の切り分け構造と電光掲示板モード

メイン関数 (`main`) は、初期化、テスト実行、アプリ本番（電光掲示板）の3つのフェーズに明確に分離されました。

### メイン関数の全貌

```c
int main(void) {
    // 1. ハードウェア初期化層 (SPI / GPIO 出力方向設定)
    init_hardware();

    // 2. ユニットテスト層 (各単体機能の自動連続テスト)
    run_all_unit_tests();

    // 3. アプリケーション層：電光掲示板モード (常時無限スクロール)
    mode_ticker_board(scroll_text);

    return 0; // ここには到達しない
}
```

### 電光掲示板モード (`mode_ticker_board`)

無限ループ (`while(true)`) を専用の表示モード関数内部に閉じ込めることで、`main` 関数の構造をスッキリと保ちながら電光掲示板としての常時点灯動作を実現しています。

```c
/**
 * @brief 電光掲示板モード（メッセージを常時無限ループスクロール表示）
 * @param[in] text 表示メッセージ文字列
 */
void mode_ticker_board(const char *text) {
    while (true) {
        // 美咲フォントからドットを構成し、1ピクセル送り速度 36ms でスクロール
        led_render_scroll_text(text, DEFAULT_SCROLL_STEP_MS);
    }
}
```

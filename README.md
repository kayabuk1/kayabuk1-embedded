1. ADコンバータのドライバ（Raspberry Pi Pico）
概要
MCP3002（2ch・10bit）と MCP3208（8ch・12bit）を、SPI で読み取るドライバです。
ヘッダ（.h）とソース（.c）に分け、ほかのプログラムから関数を呼ぶだけで使える形にしました。
repeating_timer で一定間隔ごとに全チャンネルを読み取り、チャンネルごとに現在値・最大値・最小値を記録します。
値を取り出すときは、割り込みを一時的に止めてからコピーし、読み取りの途中で値が書き換わらないようにしています。
電圧（mV）への変換は、浮動小数点を使わず整数演算で行っています。
開発中に起きた問題と対応
受信データがすべて0になった 受信した3バイトを16進数で表示して確認したところ、すべて 00 でした。MISO（GP4）を3.3Vにつなぐテストで Pico 側の受信が正常に動くことを確かめ、配線の問題に絞り込みました。原因は、チップの DIN と DOUT を逆につないでいたことでした。
測定値が本来の約半分になった（MCP3208） 送信ビットのスタートビットが1クロック遅い位置にありました。データシートのタイミング図を見直したところ、制御ビットのあとにサンプリング用の1クロックがあり、それを数えていなかったため、最下位ビットが3バイト（24クロック）に収まっていませんでした。スタートビットの位置を直し、受信データと測定値で修正を確かめました。
今後の予定
MCP3008（8ch・10bit）との切り替えに対応する
複数回の測定値を平均して、下位ビットの揺れを抑える

3. 8x8 マトリクスLED（Raspberry Pi Pico）
Raspberry Pi Pico と 74HC595・74HC138 を使った、8x8 マトリクスLED の表示プログラムです。
1行ずつ高速に切り替えて点灯する方式（ダイナミック点灯）で表示しています。
英数字に加えて、日本語（wchar_t）の表示にも対応しました。
2人で制作し、回路は相方、コードは主に横須賀が担当しました。

5. 自律走行ライントレーサー（ATmega328P / Arduino）
ハードウェア構成
マイコン： ATmega328P（Arduino UNO互換）
モータードライバ： DRV8835
センサー： 赤外線アナログラインセンサー × 3（左・中央・右）
ノイズ対策： モーターから出るノイズや電圧の落ち込みを抑える目的で、モーター端子に 0.1μF、ドライバの Vm-GND 間に 470μF のコンデンサを追加しました。
ソフトウェア
状態遷移（FSM）での制御： 最初は if-else の条件分岐だけで制御していましたが、動作が複雑になったため、enum と switch-case で動作を状態（直進、ズレ修正、クランク旋回、コース復帰、向き合わせなど）に分けて管理する形に書き直しました。あわせて delay() で処理が止まる場面を減らし、センサーを読み続けながら判断できるようにしました。
P制御（比例制御）： 左右のセンサー値の差に比例して、左右のモーターの速度を変えるようにしました。オン・オフだけの制御に比べて、蛇行が小さくなりました。
コースアウト時の復帰： 最後に線を検出したセンサーを記録しておき、復帰のときは、線があった側から探し始めるようにしました。
開発中に起きた問題と対応

開発中の不具合は、シリアル出力のログを見ながら原因の仮説を立て、一つずつ確かめました。
グレーラインの上で前後に往復してしまう（エラー8・9）： センサーの可変抵抗を調整して、白とグレーの読み取り値の差を広げ、そのうえでプログラム側の閾値を見直しました。
クランクでコースアウトする（エラー19・23）： 線を見つけた直後、車体が斜めのまま進んでしまうことが原因でした。線と平行になるまで向きを合わせる状態を FSM に追加し、向きを整えてから前進するようにしました。
